# Release and submission checklist

This list distinguishes a useful preview from a complete competition entry.

## Prepared

- [x] Official submission requirements and current deadline checked.
- [x] English product narrative and honest implementation disclosure written.
- [x] Three-minute English demo narration and storyboard written.
- [x] Eight-slide English pitch exported as editable PPTX and PDF, then visually checked.
- [x] Three-minute English-captioned emulator preview assembled from actual interaction and still captures.
- [x] Device, accessibility and live-network rehearsal checklist written.
- [x] Target repository identified: [openai-lover/seeker_FOR-THE-RECORD](https://github.com/openai-lover/seeker_FOR-THE-RECORD).

## Build and evidence

- [x] Current Flutter analysis is clean and all 84 tests pass; the backend suite passes 40 tests.
- [x] Eight-language layout checks pass, including a 360-pixel viewport at 200% text scale.
- [x] Android emulator integration passes with real SQLite, native elapsed time and native missing-wallet handling.
- [x] Build the ARM64 preview APK, version 0.3.0/code 2003. [Signing type and SHA-256 are recorded](DOWNLOAD_LINKS.md).
- [ ] Retain the final published source commit alongside the artifact hashes.
- [ ] Install and complete the new APK's main journey on a physical Android device.
- [ ] Complete physical-device TalkBack, keyboard interaction, font and reduced-motion checks.
- [ ] Verify the direct MWA/public-RPC journal path, including account changes, timeouts and rate limits.
- [ ] Capture successful real-wallet connection and supported finalized activity.
- [ ] Keep optional cloud rooms and SKR purchases unavailable until their separate backend is configured.
- [ ] Keep offline behavior and honest unavailable states intact.
- [ ] Check source and artifacts for private notes, credentials and signing material.

## Required public artifacts

- [ ] Public or explicitly judge-accessible source and commit history.
- [ ] Exact installable ARM64 APK download with SHA-256 and preview/production signing disclosure.
- [ ] Playable three-minute demo link with honest capture source and build version.
- [ ] English PDF/PPTX pitch link.
- [ ] Test every link without the owner's existing sign-in session.

## Owner decisions and final submission

- [ ] Sign in to the [official portal](https://solanamobile.radiant.nexus/) and complete the builder profile and registration.
- [ ] Verify actual project start date, ownership, funding status and eligibility.
- [ ] Confirm the final team roster and representative. AI development assistance does not invent human team members.
- [ ] Transfer prepared text into the actual private form, respecting its displayed limits.
- [ ] Ensure any new live claims match fresh device/video evidence.
- [ ] Review all materials before the final agreement, because the FAQ says final submission locks editing.
- [ ] Owner completes the required agreement and final submission before **9 October 2026, 15:59 KST**; recheck the live portal.
- [ ] Save the submission confirmation and the exact submitted commit/artifact hashes.

## If selected

Prepare the owner-controlled release signing key, publication assets and a verified privacy notice. Follow the organizer's finalist identity-check instructions. The binding terms can require the winning application to be publicly listed in the Solana dApp Store within 30 calendar days of the announcement. A review request alone does not satisfy that listing requirement. See [official terms](https://solanamobile.radiant.nexus/legal/clock-in-terms.pdf).
