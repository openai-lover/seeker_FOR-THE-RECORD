# Seeker 실기기 검증 체크리스트

현재 APK는 개발 서명·release 최적화 빌드입니다. **Functions 배포와 RPC Secret 설정 전에는 3~10, 17의 서버 연결 검증을 완료할 수 없습니다.** 기존 데이터가 있는 기기에서는 먼저 JSON 내보내기를 하고 `adb install -r`로 업데이트합니다. 서명 충돌이 나면 앱을 삭제하지 말고 중단합니다.

1. `artifacts/workroom-arm64-preview.apk`를 Seeker에 설치/업데이트한다. 기존 프로젝트·집중·결과가 유지되는지 확인한다.
2. Seed Vault Wallet을 준비하고 mainnet 계정을 확인한다. 시드/개인키를 Workroom에 입력하지 않는다.
3. Workroom의 기록 → 매매 일지에서 지갑 연결을 누른다.
4. MWA에서 Seed Vault Wallet을 선택한다. 지갑 미설치 안내도 별도로 확인한다.
5. `workroom-seeker-6984.web.app` identity의 challenge **메시지**를 검토하고 승인한다. 취소 시 로딩이 종료되고 앱을 계속 쓸 수 있어야 한다. 자산 전송 승인 요청이면 중단한다.
6. Firebase custom-token 로그인 성공을 확인한다. 오류/네트워크 단절 시 재시도 가능하고 개인 작업은 유지되어야 한다.
7. 앱의 지갑 주소가 선택한 계정과 일치하는지 확인한다.
8. 설정 → 지갑에서 Seeker 확인을 실행한다. 실제 SGT 서버 검증 성공 시에만 Seeker Verified 표시가 나타나야 한다.
9. 실제 최근 지갑 활동을 조회한다. 첫 페이지 최대 20건, 이전 거래 추가 조회 및 실패 후 재시도를 확인한다.
10. 지원 범위에 해당하는 실제 Jupiter swap 하나를 Explorer와 대조한다. 서명/시간/입출력 mint/정확한 수량/fee를 확인한다. wSOL과 native SOL을 혼동하지 않아야 한다. 실패·미지원 거래는 작성 대상이 아니어야 한다. 해당 거래가 없으면 이 항목은 미검증으로 남긴다. 테스트를 위해 새 매매를 실행하지 않는다.
11. 이유 → 계획 → 감정 → 다음 행동을 입력해 로컬 일지를 저장한다. 프로젝트 연결은 선택이다. 복기/메모 수정/삭제도 별도 일지로 확인한다.
12. 앱 프로세스를 종료한다.
13. 다시 실행한다.
14. 원본 거래 사실 및 작성한 journal이 유지되는지 확인한다. 선택한 Project Book에서 집중 기록과 함께 시간순으로 나타나는지 확인한다.
15. 지갑 연결을 해제한다.
16. 개인 Workroom 프로젝트·집중·기존 결과와 로컬 매매일지가 그대로 남는지 확인한다. 비행기 모드에서도 읽을 수 있어야 한다.
17. 같은 지갑을 다시 연결한다. 다른 계정으로 변경할 때 이전 활동 응답이 섞이지 않는지도 확인한다.
18. 같은 거래를 다시 선택하면 기존 일지가 열리고 중복 생성되지 않는지 확인한다.

추가 회귀: 한국어/영어 전환, 큰 글씨, 알림 거부, 집중 중 잠금/force-stop/재부팅 후 시간 복구, 다음 행동 이어가기, 책장·성취, 공동 집중(실제 두 지갑), SKR 거래 가드. 이번 매매일지 검증에서는 결제를 활성화하거나 SOL/SKR를 전송하지 않는다.

검증 결과에는 기기/OS/앱 버전, 날짜, 각 항목 통과/실패/미검증을 기록한다. 서명/지갑 주소가 있는 결과를 외부에 공유하기 전에 검토한다.
