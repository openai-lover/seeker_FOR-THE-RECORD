# Seeker 실기기 확인과 3분 데모

## 실제 필요한 준비

- 실제 Seeker 1대: USB 디버깅, Seed Vault Wallet 설정, 본인 소유 SGT가 있는 계정. 개인키나 복구 구문을 개발자/채팅에 전달할 필요 없음.
- 두 기기 장면: 별도의 SGT를 가진 동료와 두 번째 Seeker. 현재 확보/테스트했다고 가정하지 않음.
- 설정된 Firebase 백엔드와 앱 HTTPS identity. mainnet RPC는 Functions secret에만 보관.
- 결제는 사용자가 구체적으로 승인한 수량·수취 지갑·SOL 수수료 한도에서만 시험. 현재 실제 송금 없음.
- 최종 지원 주소·개인정보/삭제 안내·출시 서명·Store 요구 사항 준비. 개발 서명 APK는 제출본이 아님.

## 개인 기능 기기 시험

1. `adb install -r artifacts/workroom-arm64-preview.apk` → 지갑 없이 프로젝트 생성 → 1분 진단 세션 → 결과/다음 행동 저장.
2. 같은 프로젝트의 다음 행동을 불러 새 25분 세션. 화면 잠금 25분, 복귀, 결과는 직접 저장해야 하는지 확인.
3. 각 경우를 따로 기록: HOME 이동, 화면 잠금, `adb shell am kill app.workroom.seeker_workroom`(백그라운드), 최근 앱 제거, 설정의 force-stop. 시작/종료 monotonic 근거를 확인.
4. wall clock 변경은 남은 시간에 영향을 주면 안 됨. 재부팅 후에는 시간 확인 화면이 떠야 하며 자동 페이지/성취를 주면 안 됨.
5. 알림 거절·배터리 절전·Doze·전화 수신·pause/resume·조기 마무리. 정확 알람 권한은 사용하지 않으므로 지연 알림과 기록 정확도를 분리해서 판단.
6. JSON 파일 내보내기 실제 저장 위치, 프로젝트/페이지 삭제 범위, APK 업데이트 후 기존 SQLite 기록 보존.
7. 큰 글자·TalkBack 탐색·각 버튼 이름·대비·감소된 모션·햅틱 off. 자동 확대 테스트는 실제 TalkBack 검증을 대체하지 않음.

## 연결 기능 기기 시험

- 지갑 없음·취소·계정 변경·서명 거절·서버 세션 만료 → 개인 작업은 계속 가능해야 함.
- 실제 SGT 보유/미보유/잔고 0/전송 후 기존 계정/RPC 장애를 구분. 앱 문구는 소유 지갑 확인이라고만 설명.
- 두 SGT의 초대 입장, 같은 SGT 두 자리 거절, 만료 코드, 세 번째 입장과 동시 입장.
- 양쪽 ready → host start → 같은 시작 시각. 기기별 첫 표시 오차와 네트워크 지연 측정.
- 한 기기 잠금·오프라인·leave·일찍 마무리해도 다른 기기 타이머와 결과 저장이 유지되는지 확인.
- 개인 의도·프로젝트명·결과·다음 행동이 상대 화면이나 Firestore room 문서에 없는지 확인.
- 구매 전 실제 mint·정수 SKR 수량·수취 지갑·SOL 수수료 안내, 지갑 거절·잔액 부족·blockhash 만료.
- 서명 후 앱 종료/응답 끊김 → 기존 주문 조회. finalized 이전에는 성공/소유권이 없어야 함.
- host 구매 후 두 기기 표현 변화, 다음 방에도 재사용, 동일 지갑 재설치 복원, guest 영구 소유권 없음.

## 촬영 순서 (2분 55초)

| 시간 | 실제 화면 | 말할 핵심 |
|---|---|---|
| 0:00–0:20 | 내 프로젝트 책과 지난 다음 행동 | “오늘은 어디서 시작할지 이미 적혀 있어요.” |
| 0:20–0:40 | 두 Seeker의 개인 준비 화면 | 각자의 의도는 비공개. 25분을 함께 시작 |
| 0:40–1:00 | 코드 초대·두 자리·ready·host start | 공개 매칭이나 채팅 없이 아는 동료 한 명 |
| 1:00–1:20 | 잠금/복귀·각자 마무리 | 타이머가 결과를 인증하지 않음. 개인 기록은 독립적 |
| 1:20–1:40 | 결과 한 줄·다음 행동·책 페이지 | 핵심은 사용자가 직접 남기는 다음 시작점 |
| 1:40–1:55 | 실제 SIWS·SGT 확인 | “SGT로 Seeker 소유 지갑을 확인합니다.” 공식 배지/집중 인증으로 표현하지 않음 |
| 1:55–2:25 | 팩 미리보기·명시적 승인·체인 확인·두 화면 변화 | host 한 명이 사고 초대한 동료도 사용 |
| 2:25–2:45 | 다음 만남·같은 책갈피·복원 | 재사용할 이유를 실제 기록으로 설명 |
| 2:45–2:55 | 미검증/테스트 범위 자막 | 두 실제 Seeker 여부, 실제 mainnet 여부를 정확하게 밝힘 |

25분을 영상에서 줄이면 “시간 경과 편집”이라고 표시합니다. 조기 마무리 데모라면 그것을 명시합니다. `test/goldens`의 예시 기록은 사용자 실적이 아닙니다. 실제 구매·두 번째 기기가 준비되기 전에는 해당 장면을 완료한 것처럼 합성하지 않습니다.

테스터 수·재방문율·실제 매출은 아직 수집하지 않았습니다. 심사 근거로 사용할 경우 동의받은 실제 Seeker 사용자 몇 쌍의 반복 사용과 각자의 다음 행동 재사용 사례를 별도로 남기세요.
